# Project Context

## Purpose

The MSDSP Applied Learning Portal demonstrates how a postgraduate Data Science and Product Development programme can combine academic governance with authentic workplace delivery. It is an evidence-and-review prototype, not yet a production student information system or the final Gamification Management System.

## Institutional and programme context

- Programme: M.Sc. Data Science and Product Development
- Centre: Centre for Digital Innovation and Product Development (CDIPD)
- Institution: Digital University Kerala
- Delivery intent: work-integrated, project-led and professionally immersive
- Programme duration represented: four semesters
- Delivery structure represented: 20 Learning Cycles / official Levels

The portal content is grounded in:

1. The proposed programme/course-plan material represented in the supplied programme explorer.
2. `MSDSP_Course_Coordination_Plan_v4.xlsx`.
3. The supplied gamification rubric and subsequent governance clarifications.
4. Product decisions recorded during iterative prototype design.

## Approved prototype decisions

| Area | Current decision |
|---|---|
| Learning Cycle | One Learning Cycle maps 1:1 to one official Level |
| Programme hierarchy | Programme → Semester → Learning Cycle/Level → Sprint → Assignment → Evidence → Review |
| Academic authority | The Course Plan is the system of record for academic marks |
| Gamification | Separate motivational and progression overlay |
| Attendance | Managed exclusively in DUK@360 and excluded from MSDSP calculations |
| Certification | Track suggested certifications; any two completed remains the current academic interpretation |
| Mentor authority | Mentors guide, review and recommend; they do not publish official marks or progression |
| Course Details | Available only within Course Head and Mentor workspaces, not the Student workspace |
| Student reference content | Information, FAQs and abbreviations live on the separate Information Centre page |

## Pedagogical position

The prototype prioritises evidence of advanced postgraduate work over activity surveillance or generic quiz completion.

- Bloom’s Revised Taxonomy: emphasis on **Analyse, Evaluate and Create**.
- Kolb’s Experiential Learning Cycle: experience, reflection, conceptualisation and experimentation.
- Authentic assessment: product briefs, specifications, architecture decisions, code reviews, test evidence, runbooks, client communication, demonstrations and retrospectives.
- Transparent evaluation: named criteria, supporting evidence, faculty judgement and revision history.
- Work-integrated learning: realistic roles, dependencies, checkpoints, escalation paths and professional standards.

## Product evolution

The prototype evolved from a general learning-work dashboard into three role-specific workspaces:

- A realistic, gamified Student workspace centred on the learner’s next best action.
- A Mentor workspace covering Domain Mentor and Student-Team Mentor lifecycles.
- A Course Head workspace covering programme structure, course coordination, Level planning and academic governance.

The later iterations added:

- A full Course Details view for Faculty/Mentor use.
- A spreadsheet-grounded Course Coordination module.
- Programme workflow and Level 0 architecture explanations.
- Colour-coded and motion-aware Mermaid workflow diagrams.
- Badges, online-course completion, skills achieved and a student calendar.
- Separation of academic marks, mastery/gamification and attendance.

## Current status

The current build is a professional interactive prototype with mock data. It demonstrates intended information architecture and workflows but does not provide production authentication, durable records, real file storage, DUK@360 integration or regulatory result publication.

All unresolved rules must remain configurable and visibly provisional until ratified by the Programme Board. See [Programme Rules Decision Register](PROGRAMME_RULES_DECISION_REGISTER.md).
